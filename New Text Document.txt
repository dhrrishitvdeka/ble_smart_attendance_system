Build a complete BLE-based Smart Classroom Attendance System with the following architecture:
Teacher Laptop = Primary BLE Device + Attendance Controller
Student Android Phone = BLE Client + Authenticated Student Device
Optional Student Phone = BLE Relay
The system must verify student presence using BLE communication, student authentication, temporary attendance sessions, challenge-response, and proximity evidence.
Do not claim that BLE alone proves physical presence.

9. Proximity Verification
Use BLE proximity evidence as one part of verification.
Collect RSSI where possible.
However:
RSSI must NOT be treated as an exact distance measurement.
RSSI is affected by:
* Walls
* People
* Furniture
* Phone orientation
* Bluetooth interference
* Device hardware
Therefore the system should classify RSSI as:
Proximity Evidence
not:
Exact Distance

11. Relay Rules
A student phone must never automatically become a relay.
Relay mode must only be active during the current attendance session.
The relay should:
* Receive an authenticated message.
* Validate the session.
* Check message ID.
* Check hop count.
* Forward the message.
* Never modify the student's identity.
* Never modify attendance status.
* Never create attendance records.
* Never authorize attendance.
The teacher laptop remains the final authority.

29. Critical Design Principle
The final system must distinguish between:
BLE Detection
      ?
Communication
      ?
Proximity Evidence
      ?
Identity Authentication
      ?
Challenge Verification
      ?
Attendance Authorization
Do NOT implement:
BLE detected = PRESENT
Instead implement:
Authenticated Student
        +
Valid Current Session
        +
BLE Communication
        +
Proximity Evidence
        +
Valid Challenge
        +
Teacher-Side Verification
        ?
Attendance Eligible
        ?
Teacher Finalization
        ?
PRESENT
The student relay feature is only a communication extension.
It must never become an attendance authority.
The teacher laptop remains the trusted BLE root device and final attendance controller.
Finally, clearly document the limitations of BLE, RSSI, Android background behavior, laptop BLE peripheral support, relay security, and phone handoff. The system should be presented as a BLE-assisted attendance verification system, not as a system that can mathematically guarantee a student's physical presence.
